# Tactical HUD checks

`bash tools/godot/tactical-hud-checks/run.sh` executes the original TypeScript GameController.hudView followed by Hud.render against canonical engine states in JSDOM and compares its ordered controls, labels, tooltips, eligibility, selected state, objectives and forecast lines against native ProjectHud. No handwritten replacement HUD/controller acts as the oracle. Source markup whitespace, SVG decoration and keyboard glyphs are removed only where comparing native textual rows.

`python3 tools/godot/tactical-hud-checks/mutants.py <oracle.json>` deliberately breaks projection semantics in isolated copies and requires behavioral failure, not compilation failure.

After building/importing the Godot project using tools/godot/env.sh, run `res://Scenes/TacticalHudChecks.tscn` headlessly. These checks exercise real Godot buttons, one-shot submission, disabled/removed/replaced/remounted callbacks, exact stamps, focus retention and native portrait binding. This is control/asset acceptance, not a claim of visual GUI acceptance.

`tools/godot/export-tactical-hud-art.ts` preserves native schema-2 portrait bindings and validates their IDs and catalog bytes. It invokes the original candidate provider only to import/verify icons; it cannot derive portrait bindings or overwrite native cards. The shared schema-1 `portrait-catalog.json` owns all eight named cards. Each HUD binding has `portraitId`, with explicit null selecting the unit idle frame. `portraitRegion` is a validated square in named-image pixels or, for generic portraits, idle-frame-local physical pixels; generic null preserves the complete frame. Generic crops flatten to the original sheet with the idle region origin applied exactly once, rather than nesting atlases. Unknown IDs, omitted choices and missing named cards fail instead of selecting a sprite. The historical checkpoint below predates this migration and is not current acceptance.

- **62 native assertions passed**, including 43 PNG SHA256 checks, source named-card versus generic-frame binding, native mounted controls and tooltips, duplicate/disabled/busy/replaced/detached/remounted callbacks, exact stamps, focus restoration, 100 repeated projections, bounded owned AtlasTexture cache, rebind/teardown cleanup, and required-icon omission rejection. Shared ResourceLoader images and AssetCatalog frames are not disposed by HUD.
- **3 native mutants killed** in isolated copied Godot projects: duplicate submission gate removed, both redundant disabled gates removed, and owned portrait release removed. Run `python3 tools/godot/tactical-hud-checks/native-mutants.py` after sourcing the existing toolchain environment. Each requires its exact behavioral failure; compilation or unrelated runtime failure is not accepted as a kill.
- Final full Godot build passed with zero warnings/errors; headless native checks exited cleanly.

The fixture covers all shipped campaign levels, source command names/keys/hints, exact intent arguments, career/formation/reaction/facing/carrier/passenger controls and reasons, destination and deployment rows, affordable/unaffordable/capped recruitment, objective hiding and no-human fallback, nullable accounts, canonical unit/tile facts, forecasts with interception/counter/support/collateral, busy holding formation, and UTF-16 unit headings. Every fixture invokes the actual original GameController.hudView method on a controlled controller with real GameSession, original Selection subclasses and BattleLog dependencies, then passes its result directly to the actual Hud.render. Constructor-only board/camera/DOM event wiring is skipped; no hudView logic is replaced or hand-assembled. Additional composition fixtures cover distinct selected/inspected units, the cross-unit formation quirk, cursor leaving the board, busy destination/support, deployment swap, tactic/disembark/recruit context, structure-only absence, valid versus invalid hover candidates, no-weapon and non-attack-weapon forecast eligibility, and exact contextual hints. This audit found no additional native HUD mismatch. This is not a browser-driven constructor/event replay. The source selection controller is verified separately. The fixture does not prove every possible custom ruleset or every UI layout. No visual desktop playthrough or GUI acceptance is claimed here.

Four additional composition-targeted projection mutants are being verified: forecasting outside candidates, forecasting without a weapon, hardcoding attack ability, and showing selected-unit controls while inspecting another unit. Their final status is reported separately rather than assumed from the passing baseline.
