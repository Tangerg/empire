# Native application-save admission

Run `bash tools/godot/application-save-checks/run.sh --verify-guard`. The pure .NET suite uses the
shipped campaign and content. Filesystem cases use a fresh generated
`/tmp/empire-application-save-*` directory and remove only their own fixture data.

The current native manual format is schema 2. It stores a canonical campaign save,
location (`campaign`, `battle`, or `camp`), and active battle state/events only when
location is `battle`. Requests are regenerated by the campaign owner from its
pending identity, sequence, post-node-effects context and canonical content. A
camp opening is generated, never independently persisted. Old application
wrappers, request fields and `atCamp` fields are rejected without migration.

Coverage includes original request reconstruction, effect/sequence stability,
external read-model mutation (with an isolated escaping-reference negative control), removed request-level and roster-binding injection,
forged camp openings, malformed settlement signals, atomic failed admission,
canonical restart/reentry, invalid regenerated-opening content, optional career shape, strict JSON/UTF-8 reads, failed atomic writes and the
separation of stored-input/filesystem errors from live programming defects.

`CampaignNavigationChecks` additionally exercises the actual F9 root callback:
malformed input and failure to prepare replacement narrative UI both preserve the
active campaign and mounted screen; a valid candidate activates them together.
