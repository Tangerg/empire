# Native quality checkpoint: canonical ownership and initial localization

This checkpoint addresses the six reproduced engine ownership defects from the
AGENTS/PROJECT_RULES audit, plus the obsolete application port, atomic save
admission, canonical tactical input projection, and the first localization slice.
It is not completion of the full quality or localization inventory.

## Intentional contract corrections

- Tactical space consumes the resolved catalog and grid capabilities after
  overrides. Installation contexts close on both successful and failed installs.
  The native tactical producer is version 2 and spatial consumer is version 1;
  obsolete five-plugin manifests are rejected, not remapped at runtime.
- One normalized catalog owns definitions. Public mutable JSON results are deep
  detached; immutable reads support hot paths. Returned weapon/effect definitions
  cannot write the live ruleset.
- Unit health validates before normalization. One relocation aggregate owns
  placement and capture invalidation without conflating deployment, transport,
  teleport, forced movement or readiness policy.
- Composed reaction/tiling owners admit action and initial/spawned dispositions.
  Invalid seeds do not consume IDs. Return admission resolves the effective player
  before unit, marker, commander or event changes.
- Registered hit-effect handlers own payload admission; reaction definitions own
  support behavior. External closed-kind checks were removed.
- The application uses one explicit tactical session port. Campaign documents use
  schema 2 and regenerate the pending battle from canonical campaign facts;
  invalid input cannot replace the active view/session. Expected storage failures
  are distinguished from programming defects.
- Input and fog share revision-bound canonical interactive cells; art metadata
  cannot decide gameplay eligibility.
- Native story/staging structure uses schema 2 and stable text references. The
  Simplified Chinese PO owns narrative wording; the TS exporter no longer rewrites
  it. The translation dependency is explicitly injected.

## Verification scope

The exact candidate compiled without warnings/errors and imported with Godot
4.6.3 .NET. Independent source re-review closed the six original findings,
including the final spawn/return admission paths. Focused external-consumer,
composition, disposition, catalog-isolation and relocation checks passed.
All 16 shipped levels also matched independently chosen actions, ordered events
and outcome state against the frozen source runs. Source-matched defeats remain
defeats; these are independent battle comparisons, not a full carried campaign win.

Actual Godot scene execution exercised screen input/fog, camera and decoration,
and the application flow through story beats, choices, autosave/resume, battle
restart, camp, overwrite dialogs, manual-load atomicity and expected storage
failures. Native process exits and teardown diagnostics were checked. Explicit
ending/settlement UI fixtures do not prove a complete victorious campaign route.

Manual desktop input could not be accepted: the cloud CUA terminal identity was
ambiguous and the distinct Run dialog lacked an accessibility provider. No launch
command was entered and no existing game/session was modified. Headless native
application execution is not a claim of manual pointer or visual acceptance.

## Remaining work

- Semantic refusal and remaining menu/staging localization are a separate,
  subsequent API slice. Objective/outcome prose, built-in display metadata, battle
  feedback and remaining player-visible diagnostics still need their semantic
  and presentation owners separated.
- Host-language formatting, meaningful method/API readability and misleading
  prototype-name cleanup remain open. Passing tests is not a quality certificate.
- Manual GUI acceptance, final exported-package revalidation and macOS execution
  remain separate gates. No source art or scene-coverage acceptance is implied.

See [the open audit inventory](CODE-QUALITY-AUDIT.md) and the specific composition,
catalog, persistence and localization documents for the contracts and limitations.
