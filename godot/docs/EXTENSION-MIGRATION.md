# Extension composition migration plan

**Real composition implemented; final integration acceptance is recorded in NATIVE_CHECKPOINT.md.** Updated 2026-10-21. The final default-rules regression passed all 16 independent GreyFlag battles, including 2,983 actions, ordered events and state digests. That establishes exercised default behavior, not arbitrary custom-plugin compatibility. See [built-in coverage](BUILTIN-COVERAGE.md) and [compatibility limits](COMPATIBILITY.md).

The original extension kernel is now integrated into native engine execution, not retained as a primitive-only compatibility wrapper. This document records its source-owner mapping and tested contracts. The remaining GreyFlag gates are manual presentation acceptance, distribution validation and the explicit compatibility limits below. Primitive kernel tests alone do not establish composed-engine compatibility.

## Goal and invariant

Follow [PROJECT_RULES.md](../../PROJECT_RULES.md): one composition root, explicit dependencies, replaceable capabilities and one owner per rule. Migrate composition and dispatch around the existing canonical owners; do not port their default mechanics a second time.

The source [kernel](../../packages/battle-engine/src/kernel.ts), [dependency planner](../../packages/battle-engine/src/dependency-order.ts) and [composition root](../../packages/battle-engine/src/plugins/default.ts) compose 24 capabilities through four rule plugins plus the explicit content plugin. Native [BattleEngineFactory](../Empire.Core/Composition/BattleEngineFactory.cs) now resolves those capabilities once; the convenience GrayFlagEngine constructor delegates to that same composition operation. Native installation additionally separates the spatial consumer from tactical producers, for six plugins total. Persistence records the actual installed manifest. Consumer-only bypass mutants ensure replacement changes real execution rather than merely exposing a property.

## Implemented architecture decisions

- Add a small, rule-independent capability host: typed keys with stable string IDs, plugin declarations, scoped installation context and deterministic dependency planning. Location: `Empire.Core/Composition/`. Additional keys must not require editing a closed enum. No reflection discovery, assembly loader, generic DI framework or runtime service locator is needed.
- Introduce one factory accepting explicit content, plugins and optional capability overrides. Make the existing engine constructor internal/private assembly from resolved dependencies. Move default registration into the plugin recipes and remove the old assembly path. Convenience overrides must mechanically become plugins, not bypass composition.
- Keep consumer-owned narrow ports or named dependency records. Construct runtime owners from final resolved dependencies, never from independently recreated defaults. The kernel composes values; it does not execute battle rules.
- Add one shared keyed-registry mechanism, with a priority specialization where needed. Domain registries retain key extraction, dispatch and concrete clone construction. Do not put content installation or business transitions in the base.
- Derive persistence identity and supported rule names from the actual composition. Preserve [Battle](../Empire.Core/Transactions/Battle.cs) as the transactional state writer and [EcmaJson](../Empire.Core/Determinism/EcmaJson.cs) as the JSON boundary.

## Exact mechanics to preserve

Kernel installation rejects duplicate plugin identities, competing introducers/overriders, missing dependencies and cycles. Overrides run after their introducer and before consumers. Actual provides/overrides must match declarations in both directions; every install-time `require` must be declared, but an unused declared requirement is legal. Contexts close at callback completion, including exception paths; retained `provide`, `replace` and `require` operations fail. Post-composition reads belong to the composed capabilities, not installation scopes. `has`/`providerOf` probes are not consumption. `providerOf` retains the introducer identity. Anonymous overrides are separate plugins and cannot be persisted.

Registry `Register` rejects duplicates; `Replace` is **upsert**, preserving an incumbent's insertion position or appending a new key. This differs from capability replacement, which requires an introducer. Keys/All are detached, insertion-ordered collections. Seal is idempotent and blocks both writes. Clone creates an independent, mutable table with shared rule-entry identities, including when the source is sealed. Content catalog deep-copy/freeze behavior is separate; do not deep-clone delegates in the registry base. Priority order is numeric priority then ordinal UTF-16 ID order, not registration order or locale order.

## Milestones and acceptance gates

1. **Shared contracts:** consolidate registry mechanics; test duplicate rejection, upsert, ordering, ask/demand behavior, seal and shallow clone isolation. Preserve Battle's protection from later caller registry mutation and campaign frozen-clone isolation.
2. **One real composition path:** implement manifests, ordering and scoped consumption; migrate all default construction through the root. Prove replacement reaches an install-time consumer, missing/ambiguous declarations fail, two engines remain isolated, and manifests describe actual composition.
3. **Command/spatial/account slice:** custom action, custom weapon-using ability, spatial replacement and resource adapter/holder must reach queries, execution and AI consistently. Preserve rollback and event isolation. Update application callers only after the current presentation integration.
4. **Combat/lifecycle slice:** custom modifier, hit effect, rank policy, status hook, turn policy and departure listener must execute through existing owners. Check commander departure, transport consequences and delayed-cast cancellation order.
5. **Scenario/admission/save slice:** custom condition → effect → objective must work end-to-end, including nested traversal and reference rejection. Named-plugin save/load/replay must resume exactly; anonymous overrides must be refused. Changing a plugin version must invalidate incompatible documents.
6. **Compatibility gate:** port the source extension tests below, prove architecture guards with deliberate violations, and rerun all 16 default battles plus affected focused suites. A passing kernel-only test does not establish end-to-end extension parity.

Primary source tests: [kernel-resources](../../packages/battle-engine/src/__tests__/kernel-resources.test.ts), [dependency-order](../../packages/battle-engine/src/__tests__/dependency-order.test.ts), [extension-contracts](../../packages/battle-engine/src/__tests__/extension-contracts.test.ts), [engine-extension-seams](../../packages/battle-engine/src/__tests__/engine-extension-seams.test.ts), [extension-points](../../packages/battle-engine/src/__tests__/extension-points.test.ts), [rule-references](../../packages/battle-engine/src/__tests__/rule-references.test.ts), [statuses](../../packages/battle-engine/src/__tests__/statuses.test.ts), [battle-save](../../packages/battle-engine/src/__tests__/battle-save.test.ts) and [architecture-boundaries](../../packages/battle-engine/src/__tests__/architecture-boundaries.test.ts).

The completed slices remove superseded paths rather than keeping parallel defaults. Constructor and standalone harness migrations are covered by the full native build and focused source tests.

## Caveats requiring explicit tests or decisions

- The source [TacticalRulesPlugin](../../packages/battle-engine/src/plugins/default.ts#L79) captures local grids before later overrides. The source fixture preserves that defect, but native `engine.tactical-space` explicitly requires resolved content/grids and installs after replacements. Actual movement, fog, save/resume and replay regression tests cover replacement and a new grid ID. No lazy lookup or compatibility path is retained.
- Source reaction commands can commit an unknown stance, and face commands can commit a direction the current tiling does not declare. Native `UnitDisposition` validates against composed reactions/tiling before writes; commands refuse atomically and level/save admission uses the same direction predicate. These source defects are characterized separately, not preserved.
- Hit-effect `Validate` belongs to the selected handler alongside execution and description. Generic content admission does not branch on effect kind; a replacement owns its payload references. Default status duration admission reuses `StatusTransitions`. Reaction support modifiers and triggered rank progress likewise belong to reaction definitions rather than a literal ID test. New/custom and replacement policies are exercised through dispatch and persistence.
- Native AI priority now preserves source double values and ordinary fractional ordering. Mixed NaN priorities can make the source comparator non-transitive; native stable sort retains accepted values and comparator semantics, but does not claim V8-specific ordering for inconsistent comparisons. See registry-checks documentation.
- The 27 campaign registry cases are now executed by campaign-checks, including frozen-clone isolation.
- Native integer-domain and malformed-document restrictions remain documented in [COMPATIBILITY.md](COMPATIBILITY.md). Extensible composition alone does not remove those restrictions, establish arbitrary plugin safety, or provide custom presentation.

## Current implementation boundary

The required composition milestone is implemented: one factory, six native plugin recipes, 24 typed capability keys, required named dependency records, resolved runtime consumers, sealing and actual plugin manifest identity. Initial state and spawn construction now share resolved catalog/grids; custom initial facing no longer falls through a fixed grid-ID switch. The tactical producer version is now 2 and the new spatial consumer version is 1; old five-plugin documents fail manifest admission. This deliberate identity break does not alter default battle states, events or digests.

All domain slices are wired into real consumers: spatial/action/ability/resource policies; modifier/hit-effect/reaction/departure/rank policies; turn/status lifecycle; condition/effect/objective registries and objective-aware AI; ordered live references and replaceable save reader. No permanent TypeScript bridge, second default engine assembly, invented unsupported-handler fallback, or closed semantic-ID whitelist is used. Status and damage transitions retain single canonical writers.

Verification is layered: the root suite exercises named nondefault plugins through create/dispatch/save/load/replay and rollback; per-domain source differential suites cover their own handlers; compiled bypass mutants prove actual dependency use; complete default battles and the native presentation aggregate are separate acceptance gates. The former fixed-construction checkpoint and primitive kernel proofs are not being relabeled as root integration evidence.

Remaining boundaries are explicit: source comparator behavior with mixed NaN priorities is not a V8-permutation claim; documented structural/numeric/timestamp safety differences remain; arbitrary user-authored plugins are not universally proved. Latest manual GUI acceptance, standalone export/platform acceptance, and nine absent authored scenery files are independent remaining migration gates, not engine policy stubs. Other themes/editor remain deferred until GreyFlag quality is accepted.
