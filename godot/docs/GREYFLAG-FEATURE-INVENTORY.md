## How to read the evidence

- **Implemented** means an executable owner exists, not that every consumer or screen has been ported. **Partial / missing** is required remaining work unless explicitly scoped out.
- **Differential** means observable output was compared with executing original TypeScript. Native contract assertions, asset checks and successful builds are different evidence and are named as such. Counts belong to their suites and must not be summed into an exhaustive-coverage claim.
- **GUI acceptance** requires exercising the actual native application. The latest reported interactive acceptance is **19:44 UTC**, before the new animation, feedback, camp, camera and lighting integration. It covered legible Chinese story/choice/briefing, real battle entry, save at turn 1, actual AI to turn 2, load back to turn 1, and confirmed restart at 1180×812. In the story shell that means the chapter backdrop; a null staging `briefingArt` means no extra briefing image. Narrator has no portrait. These are intentional absences, not permission to choose another character or scene.

The source's `chapter-three-ending` authors **four beats**, but `renderStory(ending=true)` displays the current initial beat and offers Finish; `nextBeat` refuses ending screens. `campaign-failed` has one beat. Native now intentionally preserves this quirk, including the source completion label on active failed-ending fixtures. Testing all ending data as render fixtures does not make the inaccessible beats part of normal navigation. The source beat cursor remains transient, not part of its campaign save. [NARRATIVE](NARRATIVE.md) records three unmount/remount lifetime cases where native rejects stale callbacks more strongly than an undisposed source DOM root.

The native campaign-only menu displays the source unreadable-save sentence directly rather than hiding it in the source single-battle overlay, which has not been ported. This is an explicit layout mapping. Storage parser/OS error wording is platform-specific; document errors compare source text, whereas I/O/syntax cases require a nonempty rejection. See [slot/menu boundaries](CAMPAIGN-SLOTS-AND-MENU.md). Definition defects must propagate rather than becoming misleading bad-save notices.
