## How to read the evidence

- **Implemented** means an executable owner exists, not that every consumer or screen has been ported. **Partial / missing** is required remaining work unless explicitly scoped out.
- **Differential** means observable output was compared with executing original TypeScript. Native contract assertions, asset checks and successful builds are different evidence and are named as such. Counts belong to their suites and must not be summed into an exhaustive-coverage claim.
- **GUI acceptance** requires exercising the actual native application. The latest reported interactive acceptance is **19:44 UTC**, before the new animation, feedback, camp, camera and lighting integration. It covered legible Chinese story/choice/briefing, real battle entry, save at turn 1, actual AI to turn 2, load back to turn 1, and confirmed restart at 1180×812. Later c01-01/c01-02 terrain previews were inspected, but were not interactive battle acceptance. No newer GUI pass is claimed.
- The committed feedback/camp tree passed exact staged aggregate verification, including 142 result-flow, 149 camp-flow and 145 staging assertions. Camera and bounded lighting have focused passes, but final exact staged aggregate validation passed after a texture-shutdown ownership repair, including clean process termination and the 73-assertion lifecycle suite. A success line followed by a shutdown crash is not a pass. Narrative and menu/storage have their own isolated evidence; root navigation now passes 169 assertions across 10 groups and result flow passes 150 after the stale overwrite-dialog repair. Exact staged narrative integration passed. See [checkpoint evidence](NATIVE_CHECKPOINT.md), not merely the presence of test files.

The latest isolated root navigation/result-flow build had zero warnings/errors; both processes exited 0 without error, leak or crash diagnostics. Four runtime warnings are deliberate failed-autosave fixtures. Both fresh-data refusal negative controls retained their generated sentinel before any save. These are headless integration/safety results, not actual GUI acceptance.

Native now intentionally preserves this quirk, including the source completion label on active failed-ending fixtures. [NARRATIVE](NARRATIVE.md) records three unmount/remount lifetime cases where native rejects stale callbacks more strongly than an undisposed source DOM root.

The native campaign-only menu displays the source unreadable-save sentence directly rather than hiding it in the source single-battle overlay, which has not been ported. This is an explicit layout mapping. Storage parser/OS error wording is platform-specific; document errors compare source text, whereas I/O/syntax cases require a nonempty rejection. See [slot/menu boundaries](CAMPAIGN-SLOTS-AND-MENU.md). Definition defects must propagate rather than becoming misleading bad-save notices.
