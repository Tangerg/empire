# Built-in engine coverage

Audited 2026-10-20 against the original TypeScript default composition in [plugins/default.ts](../../packages/battle-engine/src/plugins/default.ts). This is coverage of the shipped built-in rules, **not** equivalence to the arbitrary TypeScript plugin installation/replacement API. Source inspection establishes ownership; the differential suites below establish the exercised behavior, not every possible combination.

## Remaining restrictions

- Custom microkernel plugins and arbitrary capability override/registration are not supported by the native composition root. Some native registries expose register/replace/clone/seal, but that does not establish end-to-end custom plugin parity. In particular, arbitrary abilities, modifier providers, hit handlers, imperative status hooks, rank policies, resource adapters, departure listeners and replacement random sources cannot be installed through BattleEngine as they can through the TypeScript root.
- Native cell coordinates, ranges and vision radii use an integer domain. [BattleVision](../Empire.Core/Tactics/BattleVision.cs) explicitly rejects fractional radii; original [vision.ts](../../packages/battle-engine/src/vision.ts) and tactical-grid numeric loops do not impose that restriction. All shipped GreyFlag radii are integers. See [COMPATIBILITY](COMPATIBILITY.md) for numeric and validation boundaries. This restriction must not be described as arbitrary-content parity.
- Malformed document hardening is intentionally stronger in native admission. Source linter warning parity and custom plugin diagnostics are outside the built-in execution claim.
- JSON text containing lone UTF-16 code units is supported through [EcmaJson](../Empire.Core/Determinism/EcmaJson.cs) and the engine JSON save/load APIs. Default System.Text.Json string serialization is not a substitute for that boundary.
- Presentation, alternate-grid scene layout and external publication are separate from this core audit.

## Verification evidence

- All 16 independent GreyFlag battles: 2,983 native AI actions matched the live original engine's actions, ordered events and digests after the UTF-16 boundary change. This is not a claim that every campaign branch ends in victory.
- [Scenario checks](../../tools/godot/scenario-checks/README.md): 466 source comparisons, 29 real-engine steps with JSON save/reload after every action, three non-finite status API guards; the deliberate overlay-expiry defect is detected.
- [Combat checks](../../tools/godot/combat-checks/README.md): 259 cases; [progression checks](../../tools/godot/progression-checks/README.md): 175; [damage checks](../../tools/godot/damage-checks/README.md): 33. These cover more than campaign-authored examples.
- [Transport checks](../../tools/godot/transport-checks/README.md): 81 direct cases, 24 dispatch steps, four source saves/eight resumed steps, ten explicit native malformed-save guards; the deliberate capture-reset defect is detected. Deployment reports 2,519 checks.
- [Vision checks](../../tools/godot/vision-checks/README.md) cover all three tilings, fog, allies, concealment and delayed-cast projections.
- [Action/refusal checks](../../tools/godot/action-refusal-checks/README.md) cover 27 source action outcomes, 96 resource queries and 62 announcements, isolating source error distinctions, non-finite normalization before unlimited-account checks, and account lookup before zero-amount announcement shortcuts. The audit found these residuals; they were repaired rather than classified as acceptable fallbacks.

Counts describe their named suites, not a summed independence or exhaustive-coverage metric. After the final refusal-message/resource-query audit fixes, all 16 independent battles were rebuilt and rerun: all 2,983 actions, ordered events and state digests still matched.
