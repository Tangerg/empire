This records the recovery implementation at `9c0f0fc93`. The subsequent
[ordered displacement refinement](DISPLACEMENT-FEEDBACK-20261103.md) retains its
actual-amount and visibility contracts, but now leaves actors in event order

that earlier implementation, not the current animation policy.

## Reproduction and scope

The unchanged C01-01 recorded action 99 is a human `endTurn`. Unit 12, a legion
shield guard, recovers from 73 to 93 HP. The canonical receipt contains
`regen(unit: 12, amount: 20)` and state advances from `4ac5e6b3` to `4ca73b55`.
Before this fix, the mounted native screen produced neither a recovery journal
entry nor a healing effect. The native regression failed on that exact omission,
after confirming the original command, ordered events and final state.

This batch adds localized recovery text and the existing green healing effect.
It does not change health, regeneration rate, cap, turn timing, commands, AI,
maps, artwork or save semantics. The display uses the emitted actual amount,
not the terrain's nominal rate or a difference between snapshots.

## Owners and visibility

- `BattleLifecycle.RefreshActor` and `UnitHealth.Heal` still own the health
  transition and the positive actual-amount event. No synthetic `heal` event is
  generated by presentation.
- `BattleEventText` formats the receipt; `BattleScreen` appends its description
  only through the existing ordered `EventPresented` path. Revision ownership
  prevents a later refresh from replaying the effect or journal entry.
- `BattleEventVisibility.UnitWasAndIsVisible` is the shared privacy rule for
  recovery prose and animation: the unit must be visible in both boundary
  snapshots. A null set means unrestricted visibility, while an empty set means
  no visible units. The context freezes the injected authoritative sets; playback
  also freezes after-visibility at entry and retains that same snapshot through
  animation, cancellation and final rendering.
- `GrayFlagSession` obtains visibility from the composed engine. No presentation
  code recreates vision ranges or fog rules. This change does not claim to
  redesign the visibility policy of every pre-existing event presenter.
- `BoardView` reuses `AnimateImpact` and the existing healing asset binding. It
  also requires an after-state unit and an actual drawn actor, so a unit removed
  by a later trigger cannot leave a recovery ghost. Coordinates mean the visible
  settled position, not a newly invented event-time position.

The conservative two-boundary policy is necessary because `turnStart` repaints
the settled state before later regeneration effects, and turn-start scenario
triggers may run after regeneration. A receipt does not carry event-by-event
visibility snapshots. Newly revealed or newly concealed units therefore receive
no recovery disclosure from this presenter.

Effects remain children of the existing presentation layer and use its bounded,
cancelable timeline. This preserves Godot's parent/child lifetime and explicit
dependency model rather than introducing a second animator or direct global log
writer. References: [Node lifecycle](https://docs.godotengine.org/en/stable/classes/class_node.html)
and [scene organization](https://docs.godotengine.org/en/stable/tutorials/best_practices/scene_organization.html).
