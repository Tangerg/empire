# Tactical selection composition

`TacticalSelectionController` is the single presentation owner of selection, cursor and inspection intent. It ports `packages/game-ui/src/ui/selection.ts` and the input methods in `game.ts`. It does not dispatch, advance battle state, compute legality/combat damage, run animation or manage undo history.

`ITacticalSelectionQueries` supplies detached, revision-bound canonical facts. Preserve move-stop, command, target, actor and grid-direction order. `TacticalAttack.SplashDamage` is the sum of non-primary unit damage and non-primary structure damage, not primary or support damage. `TerrainDefense` is the source's base terrain defense. `Hostile` comes from ability engagement metadata. An adapter must not silently mix revisions or hide query errors.

Integration sequence:

1. Bind a revision-scoped adapter with a unique screen binding generation. Read `Selection`, `Overlay()`, `ShowTactics` and inspection for controls; do not maintain a second selected-unit/destination/target controller.
2. Deployment roster controls call `PickDeploymentUnit`, never simulate a board click: a board click can swap the previously picked unit, whereas a roster click only changes the picked unit and centers the camera. Each callback captures the stamp of the view that created it. Call the matching controller method and consume camera hints/keyboard prevent-default. A request carries the same stamp and an immutable complete JSON action, or an Undo intent.
3. Validate current binding/revision and dispatch through the session. Set busy for pending dispatch/presentation, retaining the public cursor but suppressing selection overlays.
4. On accepted action or legal refusal, call `CompleteDispatch` after presentation settles with a fresh adapter. It resets composition to the phase's resting selection; it does not swallow invariant exceptions. Undo/load/restart use a fresh binding/reset, and the session must invalidate pending presentation before applying the replacement.

Selection-owned paths and targets are copied into read-only collections. The adapter returns no mutable battle object. Emitted actions are intentions, not proof of legality; session/core revalidation remains mandatory. Actions are explicitly built from JSON nodes and cross the shared `EcmaJson.ToElement` boundary, preserving authored UTF-16 identifiers including lone surrogates. The Core reference in the pure harness supplies this JSON boundary, not a second rules execution path.

Source quirks retained: command keys precede WASD only at destination; Escape precedes human-turn gating; keyboard movement is unavailable during deployment; cycling only continues after a Unit selection; equal attack scores and equal directional reach keep the first candidate; invalid targeting returns idle; disembark/tactic/recruit back defaults to idle; source deploying back also defaults to idle. `Leave` clears only the cursor and preserves inspection, even while busy; hovering an empty cell remains a different operation. The controller composes the full source `GameController.overlay`: selected-unit ring first, selection paint only for a commandable selected unit, and otherwise unitless selection paint plus inspected-enemy threat/ring relative to the first human viewer (or current player fallback). Busy suppresses active selection/inspection overlays while retaining the cursor. A selected deployment unit therefore has its ring but no movement painting in the original controller; this source behavior is preserved. A weapon-bearing helpful order can still add blast cells to the attack overlay, matching source.

Verification: `bash tools/godot/tactical-selection-checks/run.sh` executes original TypeScript selection and a real DOM-mounted GameController keyboard handler against the real source engine fixture, then compares native actions, states, paths and full controller-composed overlays, including real fog-hidden inspection. Supplemental contracts cover guards, refusal reset, deployment, support targeting and ordered ties. A real two-unit deployment roster exercises the original controller roster handler twice without dispatching a swap. Source-backed command/tactic/recruit vectors also preserve lone-surrogate ability, weapon, commander, tactic and unit-type identifiers. `source tools/godot/env.sh; python3 tools/godot/tactical-selection-checks/mutants.py` runs isolated mutants without modifying production files or Git index.

These files alone are not a production or GUI integration claim. Real session projection and BattleScreen/control wiring, end-to-end undo and native Godot interaction acceptance belong to the integrating batch.
