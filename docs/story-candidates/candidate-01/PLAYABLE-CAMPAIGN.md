# 《断冠之誓》前三章可玩战役

> 状态：已落地为连续可玩的剧情战役，而不再只是候选剧本。范围为前三章、16 场主线战斗。

## 1. 产品形态

本战役采用“剧情演出 → 战前抉择 → 作战准备 → 战斗 → 战果统计 → 战后演出”的连续 SRPG 流程。玩家从主菜单进入《断冠之誓》，在同一份版本化存档中推进前三章。

- 通用战斗核心不知道莱娅、灰旗或任何剧情名词；题材规则全部位于 `src/content/candidate-01`。
- 战役状态与战斗快照是两个聚合。`CampaignBattleBridge` 只负责把名册映射进关卡、再把战果投影回战役。
- 存档只发生在关卡之间。离开正在进行的战斗后会回到该关战前状态，避免把“半套战斗状态”伪装成可靠存档。
- 命名主角在胜利关卡中倒下会转化为跨关重伤，最低以 30% 生命、40% 士气回归；普通扈从仍可能永久阵亡。
- 选择不是纯文本分支：它会改变关系、补给、国库、战役变量，部分选择还会改变后续关卡的单位归属、停火规则、敌军倾向或目标耐久。

## 2. 启动方式

```bash
npm install
npm run dev
```

访问 `http://localhost:5173`，在主菜单选择《断冠之誓》“开始新战役”。已有有效存档时会出现“继续战役”。

## 4. 战役状态如何兑现到战斗

```text
剧本表现与选择
      ↓
CampaignRuntime（旗标、资源、关系、名册）
      ↓ beginBattle
Candidate-01 上下文策略（只处理本题材的选择兑现）
      ↓
BattleRequest / LevelData
      ↓
通用 BattleEngine + GameSession
      ↓ BattleResult
Candidate-01 战果策略（命名主角重伤、扈从真实伤亡）
      ↓
CampaignRuntime（下一节点与跨关状态）
```

目前已有的具体兑现包括：

- 双子丘陵选择冒进时，托伦会提前进入危险位置并带伤开局。
- 不接受三桥正式停火时，停火区会消失，敌方进攻倾向提高。
- 由米蕾尔主持解誓仪式时，笼中之火的誓链节点会预先削弱。
- 与凯恩共同管理钟塔时，他在沉没钟塔会成为友军。
- 接受银林渐进方案时，被控制的德鲁伊会成为第三方而非直接敌人。
- 囚禁中的伊芙拉与银林见证者保留独立所有权、颜色和 AI，但在队伍关系上属于保护方，不会被误计为歼灭目标。
- 战役补给和国库会转化为关卡资金，但不会反向侵入战斗引擎的资源模型。

## 5. 数值与技能设计

### 角色定位

- 莱娅：中坚指挥官。生命和韧性高于普通步兵，能够承受一次错误接战，但不能单骑清场。
- 米蕾尔：治疗、驱散和仪式型支援。输出不是她的主价值，关键在延长队伍容错。
- 布兰：侦察与穿插，适合踩触发点、寻找证据和执行撤离目标。
- 塔莎：工程与破坏，负责结构战和地形装置，正面生存依赖保护。
- 伊芙拉：高机动重火力，但受签名能力门槛与战场目标牵制，不能替代整个队伍。
- 托伦 / 艾琳：普通扈从基线。前者承担阵线，后者制造安全射程，二者的永久伤亡让战果仍有代价。

### 平衡原则

1. 关卡胜负优先由目标达成决定，而不是默认全歼。
2. 强技能必须通过士气、指挥资源、冷却、弹药或位置条件中的至少一种约束。
3. 每章至少同时考查机动、保护、结构或交互目标，避免堆高敌方生命制造伪难度。
4. 预测与实际结算完全一致；玩家的优势来自信息和规划，而不是重新掷骰。
5. 命名主角重伤保护只发生在“已取得胜利”的战果投影层，战斗中失去莱娅仍可触发失败目标。

## 6. 自动化试玩基线

平衡测试用与玩家相同的合法行动枚举、伤害预测、目标顾问和行动执行，让双方 AI 实际打完整场战斗；它不是直接修改胜负的脚本。

| 配置 | 覆盖 | 门槛 |
| --- | --- | --- |
| 标准倾向 0.58 | 16 关 | 全部结算；普通 AI 至少赢 11 关；每章最多失败 2 关 |
| 谨慎倾向 0.35 | 16 关 | 全部结算；至少赢 8 关；签名技能总使用量达标 |
| 进攻倾向 0.78 | 16 关 | 全部结算；至少赢 8 关；签名技能总使用量达标 |

当前标准基线为 12 胜 4 负，所有 16 关都在 15 回合以内自然结算。四次 AI 失利集中在三桥、黑旗营地、白河与无主之城：这些关卡要求保护主角、护送或多点控制，而目标导向 AI 会做出比人类更激进的路径选择。它们保留为战术压力峰值，但不允许出现合法行动死锁、必败开局或无限回合。

自动基线解决的是“是否可解、是否会卡死、数值是否落在可玩包络内”；浏览器人工试玩继续负责检查信息层级、按钮手感、战场可读性、预测可信度和真人策略容错。

## 7. 代码边界

| 层 | 入口 | 责任 |
| --- | --- | --- |
| 题材内容 | `src/content/candidate-01/index.ts` | 单位、武器、地形、战术和结构目录 |
| 关卡 | `src/content/candidate-01/levels.ts` | 16 份可校验 `LevelData` |
| 战役编排 | `src/content/candidate-01/campaign.ts` | 节点图、选择效果、题材上下文与战果政策 |
| 剧情表现 | `src/content/candidate-01/story.ts` | 小说式对白、场景、任务简报和抉择说明 |
| 素材绑定 | `src/art/candidate-01-runtime.ts` | 运行时像素素材到领域 ID 的映射 |
| 应用外壳 | `src/ui/campaign-game.ts` | 剧情、准备、战斗、结算和续关界面 |
| 通用桥接 | `src/campaign` | 状态机、战斗请求/战果、防腐层与存档模型 |
| 通用战斗 | `src/core` | 不依赖题材、DOM 或战役剧情的规则内核 |

第四章以后应继续添加新的题材关卡与演出节点，不应为剧情需要修改 `src/core`。只有三个题材都能复用的新规则原语，才有资格进入通用战斗层。
