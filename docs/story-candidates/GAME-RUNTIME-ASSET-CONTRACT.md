# 三套剧本游戏运行时素材契约

本契约管理能够直接进入战棋引擎的美术交付。概念图、设定集插图、程序几何占位图和只在大尺寸下好看的母图，均不得计为运行时完成。

## 1. 引擎基线

- 棋盘每格为 `32×32` SVG user units，见 `src/art/terrain.ts` 的 `TILE = 32`。
- 棋盘当前使用 SVG 图层。正式 PNG 通过 SVG `<image>` 嵌入，并使用 `image-rendering: pixelated`、整数坐标和 nearest-neighbor；不使用双线性缩放。
- 素材必须在 1× 尺寸可读。2×/3× 只是显示倍率，不得依赖缩放后才能辨认。
- PNG 是游戏默认格式；SVG 只用于审阅、重着色和可复现导出。

## 2. 类别规格

### 2.1 战斗与任务单位

| 项目 | 规格 |
| --- | --- |
| 单帧 | `32×48` |
| 基础移动表 | `128×48`，四帧横排 |
| 帧序 | 站立 A、踏步 A、站立 B、踏步 B |
| 脚底锚点 | 每帧 `(16,47)`，加载到棋盘格中心底边 |
| 朝向 | 源图默认朝右；朝左由引擎水平镜像 |
| 透明 | 二值 alpha；四角透明，不带烘焙地面或外框 |

骑乘、大型、载具和多格单位允许 `64×48`、`64×64` 或 `96×64` 单帧，但 manifest 必须声明 `frameWidth`、`frameHeight`、`anchor`、`footprint`和 `zOrder`。

每个兵种至少在以下三项中有两项独立设计：身体轮廓、主武器轮廓、移动方式。仅换衣服颜色不算新兵种。

### 2.2 地形与自动拼接

- 基础 tile 为 `32×32`。非连接地形至少交付 4 个外观变体，由坐标 hash 稳定选择。
- 道路、河流、壕沟、墙体、轨道、能源管线等连接类地形使用 N/E/S/W 四位邻接 mask，至少提供 16 个连接单元。
- tile 四边必须像素级无缝；验收时使用 `3×3` 与随机 `12×8` 地图拼接，不允许浅色缝、突然截断的波纹或错边墙砖。
- 地形上的工程建筑、植被、火场和洪水覆盖层不烘焙进基础 tile，便于状态切换。

### 2.3 交互建筑与地图物件

- 常用足迹为 `1×1`、`2×2`、`3×2` 格；透明画布可向上超出足迹，但脚底必须对齐 tile 边界。
- 至少交付 `normal`、`damaged`、`captured`三态；供给点、门、机械节点再增加 `disabled`，可摧毁目标再增加 `destroyed`。
- 占领颜色放在独立 mask/banner 层，不为每个玩家复制整张建筑。
- manifest 必须声明 `footprint`、`anchor`、`stateRows`、碰撞区和可交互热区。

### 2.4 装备、技能、状态与 HUD

| 类型 | 源单元 | 实机显示 | 要求 |
| --- | ---: | ---: | --- |
| 装备 / 技能 | `32×32` | 24–32 px | 轮廓先于内部纹理，禁止微缩文字 |
| 状态 | `24×24` | 16–24 px | 一个主语义，禁止两个相似圆环只换颜色 |
| HUD / 地图标记 | `24×24` 或 `32×32` | 16–32 px | 保持 1–2 px 最小线宽，适配深浅底 |

图标在原尺寸、50% 灰度和色弱模拟下都必须可区分。文字、阵营色和稀有度框由 UI 渲染，不烘焙进图标。

### 2.5 FX

- 基础单元为 `32×32`；范围、建筑和大型单位 FX 允许 `64×64`。
- 帧数只允许 4、6 或 8，水平排列；manifest 声明 `fps`、`blendMode`、`loop`、`anchor`。
- 烟、火、风沙和透明能量可使用分级 alpha；命中闪光、火花和像素碎屑优先二值 alpha。
- FX 不得把棋子轮廓完全遮盖超过两帧。

### 2.6 剧情场景

- 运行时为 `256×144` 不透明 PNG，可用 2×/3× 整数倍显示。
- 场景需预留对话框安全区，不把关键人脸、道具或地图证据放在底部 32 px。
- 雨、火、雪、回声光点等需要在游戏中开关的元素交付独立 FX，不只烘焙在背景。

## 3. 风格门槛

每套 V2 必须选用本套既有正式 `*-hd.png` 作为参考，并在同屏对比中通过以下项目：

- 材质可读：金属、布料、木材、石材、陶瓷或水面不能只是单色块。
- 光影一致：同一单元至少有暗部、中间色和高光；不滥用柔边渐变。
- 轮廓明确：在黑色剪影、灰度和实机底图上都能区分。
- 颗粒一致：不混入光滑矢量块、油画模糊边或比源像素小得多的噪点。
- 题材语义正确：画面不得为了好看加入剧本不存在的魔法、种族、现代器物或风格符号。

## 4. 生产流程

1. 从题材 manifest 选取一个可玩批次，先锁定尺寸、锚点、帧数、足迹和状态。
2. ImageGen 只生成原创高质量母图；透明素材使用平面色键底，并保存母图和最终 prompt。
3. 母图经色键去除、独立单元裁切、像素化、有限色量化、手工清边和锚点校正，输出运行时 PNG/SVG。
4. 通过机器 QA 后，还必须经过 1× 目检、同屏风格对比和游戏棋盘实机截图。
5. 只有整包全部实机通过的交付可记为 `qualityTier: runtime-v2`、`runtimeReady: true`。部分进入真实关卡时使用 `qualityTier: runtime-v2-partial`、整包 `runtimeReady: false`，并在 `gameIntegration.runtimeReadyAssetIds` 精确列出已通过项；未列出的同包资产仍是候选。

## 5. 必须通过的 QA

- 路径、尺寸、格式、alpha、色数、帧数、帧序和锚点。
- 单位四帧脚底不漂移，武器和头部不被裁切。
- 自动 tile 所有连接 mask 和随机拼图无缝。
- 建筑足迹、热区和图像脚底一致，状态切换不改变锚点。
- 图标在 16/24/32 px、灰度、深色底和浅色底上可读。
- FX 帧序、循环、混合模式和遮挡比例正确。
- 游戏演示关卡中不再回退到程序占位图，并有对应截图作为验收证据。
