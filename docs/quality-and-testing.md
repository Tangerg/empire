# 验证 SRPG 引擎改动

本页说明当前测试层次、常用命令和合并前验收门槛。测试必须验证领域不变量和跨层契约，不能只检查页面能否渲染。

> 文档类型：How-to · 状态：整仓类型、规则、应用、架构和性能测试已配置 · 测试运行器：Vitest

## 运行标准检查

从仓库根目录运行完整检查：

```bash
npm run typecheck
npm test
npm run build
```

三条命令分别验证：

- TypeScript 工作区类型和跨包导入
- 整仓 Vitest 测试
- 类型检查后构建四个应用

`npm run build` 已包含 `npm run typecheck`。本地开发时可以先分别运行，以便更快定位错误。

## 按范围运行测试

修改单个包时先运行对应测试，再运行整仓测试：

```bash
npx vitest run packages/battle-engine
npx vitest run packages/campaign-engine
npx vitest run packages/editor
npx vitest run packages/game-ui
npx vitest run packages/experience-lab
```

使用监听模式：

```bash
npm run test:watch
```

构建单文件体验包：

```bash
npm run build:experience
```

产物位于 `dist/experience-lab/index.html`。构建成功只证明资源可以打包，仍需通过 `file://` 打开并人工完成关键流程。

## 测试层次

当前测试按失败影响从内到外组织。

| 层次 | 主要目录 | 验证内容 |
| --- | --- | --- |
| 领域单元 | `packages/battle-engine/src/__tests__/` | 实体、聚合、规则和算法不变量 |
| 扩展契约 | 同上 | Action、Event、目标、场景、能力、AI 和内容隔离 |
| 跨题材契约 | `cross-theme-contracts.test.ts` | 同一通用原语表达不同题材 |
| 关卡测试 | 引擎与题材包测试 | schema、引用、AI 推演和数值边界 |
| 战役测试 | `packages/campaign-engine/src/__tests__/` | 节点、事务、战斗桥和存档 |
| 存档往返 | `battle-save.test.ts` | 战斗存档经 JSON 往返后摘要一致，且拒绝这套规则跑不了的存档 |
| 浏览器存储边界 | `packages/game-ui/src/application/__tests__/` | 非法 JSON、错误根形状和不可读条目被报告；拒绝写入时保留槽位原字节 |
| 编辑器测试 | `packages/editor/src/__tests__/` | 文档往返、工具、历史和校验 |
| 表现测试 | `packages/game-ui/src/art/__tests__/` | 图层、场景映射、帧动画、栅格素材，以及渲染器端口的生命周期（摘掉宿主之后还有没有人在要下一帧） |
| UI 集成 | `packages/game-ui/src/ui/__tests__/` | 控制器和战役界面 |
| 应用冒烟 | `apps/*/src/main.test.ts` | 真实入口安装内容并挂载页面 |
| 架构测试 | `architecture-boundaries.test.ts` | 无环、包边界、入口面、端口依赖、行为归属和同一答案只写一处，共 99 条（断言、朝向、调用形状、端口字段扫描、实体字段扫描和顶层可变状态扫描覆盖全部工作区包；错误静默扫描还包含四个应用入口） |
| 关卡拒绝语料 | `level-lint.test.ts` | 四十余份「只坏一处」的关卡，每份必须恰好报一条错 |
| 不变量巡检 | `invariant-sweep.test.ts` | 全部已发布关卡 × 三档 AI，每条指令后校验整份状态 |
| 性能基准 | `packages/battle-engine/src/__bench__/` | 核心热路径基线（只报数，不判定） |
| 性能预算 | `performance-budget.test.ts` | 最重一章 60 步 AI 的空间查询**次数**上限；计数而非计时，所以处处一致 |
| 重放扫描 | `tools/replay-sweep.ts`（`npm run --silent sweep`） | 全部已发布关卡 × 三档 AI，逐条事件加终局摘要；这是工具不是测试，答案靠 `diff` 读 |
| 棋盘 markup | `tools/board-digest.ts`（`npm run board:digest`） | 全部已发布关卡 × 两套美术的挂载后 markup，逐字节 |
| 棋盘几何 | `tools/board-flat.ts`（`npm run board:flat`） | 同上，但位置解析成绝对坐标；包装组隐形，移动一像素不隐形 |
| 棋盘规模 | `tools/board-scale.ts`（`npm run board:scale`） | 把关卡平铺放大后，每层的节点数与「不同的图 / 图的张数」复用比 |

上面三把尺子共用 `tools/board-harness.ts`：JSDOM 全局、目录和三个内容包、引擎、铺法、busy overlay、已发布关卡清单、`BoardView` 需要的五个空回调，还有 dump 用的缩放。以前三份各有一份自己的拷贝——**尺子本身就成了风险**。`board:digest` 和 `board:flat` 是拿来互读的（一个逐字节钉住 markup，一个把位置解析成绝对坐标），只在其中一份里改了 overlay，两把尺子量的就是两块不同的棋盘，而没有任何东西会说出来。现在只有「怎么读」这一件事是各自的。

## 战斗规则测试

规则测试应覆盖合法、非法和边界三类输入。每个新机制至少验证：

1. 合法 Action 修改正确状态
2. 非法 Action 抛出 `IllegalActionError` 或领域错误
3. 失败后状态与提交前完全一致
4. 预测与正式结算一致
5. 事件顺序与状态变化一致
6. 克隆后的 AI 模拟不污染原状态
7. 多引擎实例不会共享可变注册表

伤害机制还应断言 `DamageBreakdown.modifiers`，不能只断言最终数字。这样可以发现乘区顺序、来源缺失和减伤封顶错误。

## 扩展契约测试

开放类型只完成 declaration merging 不算实现。扩展测试应从装配到消费跑完整链路。

### Action 或能力

验证以下链路：

```text
类型 → 注册 → 合法性 → 执行 → Event → AI 估值 → 实例隔离
```

自定义能力缺少 AI evaluator 时，测试应明确失败或证明 AI 不会枚举该能力。不能接受静默基础分。

### 目标

目标测试需要验证：

- 描述和进度
- `pending`、`success`、`failure`
- 激活、隐藏、完成、失败和取消
- 子目标刷新顺序
- AI objective advisor
- 与场景效果的交互

### 场景条件和效果

场景测试需要验证：

- 条件只读取权威状态
- 效果只修改聚合内事实
- 一次性触发器只触发一次
- 循环触发器遵守 occurrence、起止回合和最大次数
- 新事件进入 `eventCounts`
- 失败的效果回滚整个 Action

## 关卡测试

每张生产关卡至少运行三种测试。

### 格式与引用

调用 `validateLevel(rules, level)` 并要求没有 error——它一次问完两件事：文档对着内容目录自不自洽，以及这套规则集有没有实现文档点名的每条规则。再通过 `mapFromLevel()` 与 `terrainRows()` 做地形往返。

「已发布关卡零错误」是一条永远为真的断言看起来的样子：它不能证明一张**坏**关卡会被拒。`level-lint.test.ts` 是反向语料——每份关卡只种一处毛病，断言恰好报一条错，并且这条错要点出出问题的那个名字。它先写在旧实现上跑通，再作为重构的围栏。

### AI 冒烟

让 AI 驱动双方运行固定回合数，断言：

- 每个 Action 合法
- 每个 AI 回合最终到达 `endTurn`
- 状态没有非法重叠或悬空引用
- 场景触发器没有无限循环

AI 冒烟不能代替平衡测试。它只能证明关卡可推进。

### 数值与目标

为关卡声明的设计承诺添加断言，例如：

- 关键单位不会被首回合必杀
- 增援坐标可用且 key 唯一
- 目标区域可达
- 保护目标存在并被正确引用
- 推荐回合内至少存在一条获胜路径
- 资源足以使用教学要求的能力

题材包可以增加自动审计函数，但审计必须复用引擎查询和预测。

## 编辑器测试

编辑器采用领域与 DOM 两层测试。

`EditorDocument` 测试验证：

- 地形、归属、单位、海拔、悬崖和掩体修改
- 地图缩放与裁剪
- 序列化和反序列化
- `toLevel()` 往返
- 不变量错误

`EditorApp` 测试在 jsdom 中验证：

- 工具按钮和笔刷手势
- 撤销与重做
- 自动草稿
- 玩家和规则表单
- 导入与导出数据
- 错误单位染色和检查面板
- `dispose()` 后全局快捷键和面板监听不再响应，且重复销毁安全

新增高级字段时，必须先加入往返测试。没有往返测试的字段不应出现在可视化表单中。

## 表现测试

表现测试优先验证结构和契约，不依赖像素级截图。

当前关键断言包括：

- `SceneViewport` 的 inset 和指针映射
- 道路、地面、单位和前景的 DOM 顺序
- `ArtProvider` 与 `BattlePresentation` 回退
- 栅格图集裁剪坐标
- 帧条元数据校验
- 共享 RAF 循环在空闲时停止
- 减少动态效果模式停在稳定帧
- 视图销毁时注销精灵动画，并取消有限过渡、解析其等待者

人工视觉检查仍然必要。结构测试无法发现色彩、比例、透明边缘和场景构图问题。

## 持续集成

`.github/workflows/ci.yml` 在 push 与 pull request 上跑：typecheck → 全部测试 → 四个应用构建 → 关卡重放。

重放那步不是断言而是 diff 工具，CI 没有「之前」可比，所以它检查两件 CI 能检查的事：全部 20 张关卡 × 3 档 AI 都能在上限内跑完不抛异常，以及连跑两次逐字节相同——确定性在另一台机器上也成立。

在此之前这套护栏只在本机成立。架构适应度测试只约束真正运行它们的地方。

## 架构测试

`architecture-boundaries.test.ts` 扫描源码导入。它应保持少量稳定规则，不应为每次违规增加例外。

修改包结构后至少确认：

- 核心生产依赖图无环
- 战斗内核不导入内容和表现
- 内容包不导入表现
- 引擎与内容不使用 DOM
- 编辑器文档不依赖渲染
- 游戏控制器不绕过 `TacticalSpace`
- 默认内容不在核心包导入时隐式注册
- 每条规则只有一个归属：伤害结算、单位回场、一次攻击的落地、这一格能不能站人、谁可以持有资源、一条常驻命令怎么读、一张地图的空间层谁能写、一个触发器什么时候该响、两格之间有多远、一次打击覆盖哪些格
- 每个 `XxxRules` 端口只声明本模块自己读的字段；交给协作者的服务用 `extends` 拿，不抄字段
- 实体字段只由实体自己写：规则模块不出现 `unit.hp = …`、`unit.done = …` 这类赋值
- 引擎里每一次抛出都说明白谁错了：不出现 `throw new Error(`
- 文档表格里点名的每个符号都真的存在（表格是对当下的断言，正文才可以讲被删掉的东西）

如果测试失败，先调整依赖归属。只有测试规则与真实边界不一致时才修改测试。

**守卫也要被守。** 一条守卫写着「除了这几个文件」,那份豁免名单只会朝一个方向腐烂:某个文件被清理干净、不再做那件事,而它的豁免留着。什么都不会失败——豁免本身不花钱,它只是悄悄允许那个缺陷回到一个已经没有它的文件里。

写这条检查时有**五处是坏的**:`battle-aggregate.ts` 不再结算伤害,`board-decorations.ts` 不再写死方位,`scenario.ts` / `objective-system.ts` / `types.ts` 不再点名 payload 种类——它们当初被豁免的那些梯子,正是 `references` 替掉的东西。五处全删,所有守卫依然全绿,这就是它们已经死了的证明。

这条检查覆盖把模式写成字面量的那一半守卫;另一半在运行时拼模式,读不出来,于是被逐条点名并计数。**新加一份豁免名单只会落进两个桶之一,哪个桶都不能悄悄变大。**

**属性巡检补单元测试补不到的那一半。** 单元测试说「这条规则做什么」，`invariant-sweep.test.ts` 说「任何一份状态都不许长成什么样」：一格站两个单位、乘员挂在已消失的载具上、账户为负、已阵亡者仍在咏唱、事件指向从未存在的单位。它跑十六章 × 三档 AI，每条指令后检查一次（约 1.4 万份状态、4.4 万条事件），顺带抽查存档往返与撤销重演。两条臂都用手工植入缺陷验证过，覆盖计数本身也被断言——否则一个悄悄不再覆盖任何东西的巡检会静默通过。

**行为保持要证明，不能声称。** `AGENTS.md` 要求「重放全部已发布关卡，比对事件流与终局摘要」——而这件事以前靠一个仓库外的临时脚本，丢过一次。现在它是 `tools/replay-sweep.ts`，一条命令：

```
npm run --silent sweep > /tmp/before.txt   # 改动前
npm run --silent sweep > /tmp/after.txt    # 改动后
diff /tmp/before.txt /tmp/after.txt
```

十六章 + 四张内置图，各跑 0.35 / 0.58 / 0.8 三档 AI，输出五万两千行。空 diff 才算行为保持；非空的必须逐条说清楚是什么、为什么，而不是接受它。

**已记录的一次非空 diff。** 删掉 `Unit.meta` / `BattlefieldMarker.meta` 那一轮:60 条 `END` 行里 60 个 `hash=` 全变了,而**事件流逐行相同**——`winner`、`turn`、`actions`、`reason` 全部逐字一致,把 `hash=` 抹掉之后两份输出完全相同。原因不是打法变了,是尺子变了:`meta` 离开了 state,规范形式少了键。这一次之后所有摘要基线作废,拿旧摘要比对会误判引擎坏了。它和 `invariant-sweep.test.ts` 是两件事：后者断言「状态不许长成什么样」，前者只回答「有没有任何东西变了」——那是个用 `diff` 读的问题，写成断言反而说不清。

**画面也要证明，而且需要两把尺子。** `board:digest` 逐字节钉住 markup，`board:flat` 把位置解析成绝对坐标。两者的敏感度是刻意不同的：把一个 translate 从图里搬到它的包装组上，画面完全没动而 digest 每一行都不同——那时候只有 `board:flat` 能回答问题；反过来，改一个颜色字面量 digest 立刻看得见。渲染器改动同时跑两把，各自的差异都要能逐条归因。

**把编译器的输出行数当成错误数,差了四倍。** 我上一轮说 `exactOptionalPropertyTypes` 报 242 条、代价太大所以不开——那个 242 是 `tsc` 的**输出行数**,每条错误会把解释铺开三到四行。真实数字是 **60 条**。差四倍就是「一次迁移」和「一个下午」的区别,而我拿那个数字做了决定。

现在它开着,报零条。它换来的东西是实的:`{ ...source, x: maybe }` 这种构造器再也不能把一个已经有值的字段抹成空,而这个仓库里到处是这种构造器。四十个字段现在写 `?: T | undefined`,那是**实话**——代码确实往里写 `undefined`;而「缺失即没有意见」这个读法没有被削弱,因为这里没有任何地方区分「键不存在」和「键在但是 undefined」。顺带清掉两处这个开关照出来的糊涂写法:一个 `?? undefined` 的空操作,和一个测试里「把 seed 设成 undefined」——它想说的是**这个键没了**,`delete` 才是那句话。

`noUncheckedIndexedAccess` 仍然关着,而这个也是量过的:915 条,而且几乎每一处的修法要么是 `!`(本仓库有一条守卫明令禁止),要么是在代码明知不会越界的地方硬加一个 `??` 兜底。

全部关卡的事件流、摘要和棋盘 markup 逐字节相同。

**「文件太大」不是坏味道,「东西放错层」才是。** 我上一轮说 `GameController` 和 `EditorApp` 的体量拿不出具体缺陷就没动,那是把问题问错了。按行数看它们确实还是那么大(867 / 839,注释还变多了);但里面有两处**放错层**的东西,是真的:

- 控制器自己拿 `requestAnimationFrame` 做缩放合流,配一个 `zoomFrame` 字段、`dispose` 里一次 `cancelAnimationFrame`、回调里一句 `if (!disposed)`——而 `PresentationTimeline` 存在的**全部理由**就是拥有这份取消义务,同一个包里已经有一个。现在是 `perFrame(step)`,同一份实现。
- 编辑器的导出/复制/导入是控制器里的一个 `Blob`、一次合成点击、一次 `navigator.clipboard` 和一个 `<input type="file">`;它的草稿槽位是一个裸 `catch {}`,就摆在笔刷处理旁边。而这个仓库碰浏览器边界的**其他每一处**都在 `application/` 里,拒绝写清楚、并且拿「写不进的槽位」和「装着乱码的槽位」测过。

现在有一条守卫:槽位只许出现在拥有它们的那一层。整层里唯一一处刻意的沉默——草稿写不进不该拦着人画图——写在读者会去找的地方。导航不是存储,留给外壳。

**十三个数字看着像十三次艺术选择。** 四个美术模块里手写了十三条地面阴影,每一条都是填 `PAL.ink` 的椭圆,透明度有七个不同的值:0.12、0.16、0.18、0.2、0.22、0.24、0.26、0.34。没有人是为了什么理由选 0.22 而不是 0.24——这是**同一个写法抄了十三遍,顺手把强度抖了一下**,而正是那点抖动让它看起来像一次选择。我上一轮把这类椭圆归成「画,不是读数」而放过了,那个判断是错的:大小确实是画(一座堡垒的落地面积不是一个士兵的),深浅不是。

现在是三档具名重量(0.18 / 0.22 / 0.3),大小仍归调用方。**画面的改动逐条交代**:把每条地面阴影规范化之后两份 dump **完全相同**,别的一个字节都没动;全部已发布棋盘里 168 条轻、44 条中、37 条重,最大的一次 alpha 变化是 0.12→0.18(26 个节点)和 0.34→0.30(36 个节点)。`sweep` 不变。守卫的 tell 是阴影的两半合在一起——墨色**加**一个透明度;立绘里的眼睛也是墨色椭圆,但它不透明,所以不会被误抓,也不需要豁免。

**四个界面里最没人管的,是那个承载整场战役的。** 「渲染出来的控件必须有人接」这条守卫只扫应用入口、只认 `data-act`、只认 `switch` 和查找表两种形状。而战役界面用的是**第三个**属性名 `data-campaign-act`，在同一个文件里用 if 链派发——同时落在这条守卫的范围、属性名和两种形状之外。一个 `data-act` 打错字，得到的是一个看着活、点了没反应的按钮，而最没有围栏的偏偏是它。

加宽之后不需要任何文件名单：**一个文件如果接住了它自己声明的一部分意图，就得全部接住**；一个一个都没接的，是把意图交给别处的控制器的视图（`panels.ts` 交给 `app.ts`），那一对由运行时测试覆盖。今天有四个文件在派发自己的意图，守卫断言至少查到了四个——否则把所有文件都当成「转交」跳过就能全绿。破坏验证：把 `nextBeat` 打成 `nextBeet`，当场红。

**`x!` 全仓库禁止，`x as never` 全仓库随便写。** 这两个是同一个动作——叫编译器别问了——区别只是其中一个有正当住址。注册表存 `Handler<Kind>`，注册进去的是 `Handler<'destroy'>`，而后者并不能赋给前者（处理器对它的载荷是逆变的）；让这一对成立的那个「键相关性」恰恰是 TypeScript 没法穿过一次查表表达的东西，所以派发处的那次 cast 是在替注册处的那次 cast 付账。写得正规需要一套映射类型的把戏，而那正是本仓库宁可不读的聪明写法。

所以它留下，但只留在**拥有扩展点的那些模块**里。别处出现就是在掩盖一个真的类型错误——而确实有一处是：一把尺子把 `{ width, height }` 通过 `as never` 递给 `idx`，可 `idx` 收的就是 `{ width: number }`，那次 cast 什么账都没付。

**三条围栏里有一条是靠记性的。** 公理说「规则改什么，克隆就得复制、摘要就得覆盖、存档就得携带——这三件各有一条测试兜着，而不是靠记性」。其中两条确实兜着：摘要**失败即闭合**（新字段默认被哈希，除非 `ignoredPath` 出来说话），存档由**编译器**兜着（`StoredShape<GameState>` 拒绝一张没被教过某字段的表）。克隆那条是靠记性的——`cloneState` 一条条点名要深拷的东西，`{ ...state }` 把新来的按引用捡走。

所以改成**结构式**检查而不是逐字段清单：克隆一份打完的战斗，两棵树一起走，报告任何一处「是同一个对象」。它当场找出七处：每个玩家的 `objectives` 条目、`rules.baseResourceGrants`、`rules.siteResourceOverrides`、`scenario.triggers`。这七处今天都没人写——但「按约定只读」和「只读」不是一回事，一条通过写 `objective.hidden` 来隐藏目标的规则，会从一次模拟里写进正在打的那局，而且不会有任何东西红。

**代价是量出来的，不是猜的。** 直接把 `cloneState` 换成 `structuredClone` 最干脆，能删掉六十行手写拷贝——但整轮 sweep 从 13.5 秒涨到 18.4 秒（+36%），AI 的热路径上克隆得太频繁。只补那三处则是 14.6 秒（+7%）。取后者：七个百分点换一条不用维护的围栏，而且换掉的是一类会表现为「不确定性」的、极难追的缺陷。

**一条清单的守卫抓不住一次比较。** 「不许自己写出一块棋盘的朝向清单」这条守卫的 tell 一直是**清单**：`'north'` 后面 80 个字符内出现 `'east'|'south'|'west'`。于是三处单独的朝向就在光天化日下待着：两块棋盘都按 `facing === 'west'` 决定要不要镜像，所以八方格上一个朝西北走的单位被画成朝右，而六边格上**每一个**单位都被画成朝右（它的西叫 `hexWest`）；`state.ts` 给没写朝向的单位塞 `'south'`，而六边格根本不认——偏偏 `validateLevel` 只检查**写出来的**那些，这个默认值是它看不到的；编辑器的笔刷开局指着 `'north'`。

按文档里已有的那条教训，**加宽而不是并列**：一条公理一条守卫。tell 从「清单」扩到「朝向出现在一次*决定*里」——被比较，或者被当默认值。内容不豁免，因为内容不是违规方：一张为自己方格棋盘写 `facing: 'west'` 的关卡，说的是那块棋盘确实有的方向。模式写成**一个字面量**而不是三段拼起来的，这样元守卫还能继续验证那一条豁免（`tactical-grid.ts` 依然在写朝向名）。四种形状逐一破坏验证：镜像比较、默认朝向、笔刷默认、以及原来就该抓到的清单。

修法都是问铺法：`facesLeft(grid, facing)` 走一步看 x 有没有变小，`TacticalGrid.restingFacing` 由铺法自己声明（方格是南，六边格是东南）。后者让 `createState` / `spawnUnit` 需要铺法，于是它们收一个 `StateRules extends GridRules` 端口——`BattleRuleServices` 结构化满足它。全部关卡的事件流、摘要和棋盘 markup 改动前后逐字节相同：已发布关卡只用方格四向，所以画面本来就没差别，差别在那些还没人踩到的棋盘上。

**工作区是「依赖写在声明里」唯一不自我执行的地方。** npm 把每个包都软链进同一个 `node_modules`，所以 import 一个兄弟包，manifest 提不提它都能解析。于是 `game-ui` 的测试伸手拿了四个包而它的 manifest 一个都没写，`battle-engine` 干脆连 dependency 块都没有——而它的测试和基准装配了三个内容包。还有一处更直接的：`story-candidate-01` 的一个测试**用包名 import 自己**。

现在有一条守卫查三件事：运行时 import 的必须在 `dependencies` 里，测试 import 的至少要在 `devDependencies` 里，声明了而没人 import 的算多余；再加上「不许用包名 import 自己」。只查 `@empire/*`——这是理由而不是省事：没声明的第三方 import 根本没装，会大声失败；而工具链（vitest、jsdom、vite）是**故意**只在根上声明一次的。三个分支各破坏验证一次。

顺带把四个应用的构建约定收成一句：`apps/x` 构建到 `dist/x`，以前是同样五行抄了四遍，那个词写错一个文件都不会有人发现，直到 `build:apps` 把另一个应用的产物覆盖掉。

**样式表是死代码唯一不会喊出来的地方。** 删掉用某个东西的代码，样式表里那条规则会留下来，而**一条死规则和一条活规则长得一模一样**。所以两个方向都要查：已经有一条「不发射任何没人读的 class 和 data 属性」，现在补上反过来的一条——「不选择任何代码从不发射的东西」。这一轮它找出四个自定义属性没有任何人读，其中三个是 `.campaign-root` 的头三行，读者会把它们当成战役的调色板。

有两族 class 是通过插值到 DOM 的，而两族都写在一份枚举上：`hud-${region}` 写在 `HUD_REGIONS` 上，`layer-${name}` 写在 `BOARD_LAYERS` 上。所以守卫**从那两份清单展开**，而不是按前缀放行——`.hud-ghost` 是违规，而第三族插值出现时这条会红到有人来教它。data 属性有第二种合法拼法（DOM 的驼峰 `dataset.mode`），只有这一个例外，写在代码里而不是豁免名单里。破坏验证做了三次：一条谁都不发射的 class、一条插值族内部的死规则、一个谁都不发射的 data 属性。

**抛出来的东西也要只翻译一次。** 一个 `throw` 可以携带任何值，被拒的浏览器 API 常常携带 `DOMException` 或一个裸字符串。四个外壳各答一遍：编辑器有一份私有的 `errorMessage`，两处把 `instanceof Error ? … : String(…)` 手写出来，另两处写 `String(cause)`——那个会把类名放在前面，于是玩家在两个地方看到的是「无法开始战役：Error: …」，在别处看到的是一句干净的话。现在 `errorMessage` 和它翻译的那三个错误类放在一起，守卫的 tell 是**收窄本身**：写 `instanceof Error` 就是准备自己判一次。顺带把两处 `catch (e)` 改成 `catch (error)`——另外十七处都是这么写的。

**画面的一次刻意改动，逐条说清。** 四条「还剩几成」的条：HUD 的和单位的按 0.6 / 0.3 分三档，通用结构条和题材结构条按 0.5 分两档——所以一个四成血的结构是红的，而旁边四成血的单位是琥珀色的。两条结构条还比单位条高 0.6、薄 0.6，题材那条另外写了三个**调色板里根本没有**的颜色（`#66b873`、`#d85c4c`、`#201914`，最后一个是 `PAL.ink` 的差一点）。格子上的一条杠是被当成**读数**看的，不是被当成画看的，所以同一块棋盘上的两条必须一致——这和地砖里那些手绘的接地阴影不同，那些椭圆五处各不相同是画，不是读数。

合成一条之后 `board:digest` 会变，这是**有意的画面改动**，所以要精确交代：全部已发布棋盘里一共 9 条结构条，9 条全部换成共用的几何与调色板颜色，把每条杠规范化之后两份 dump **只差那句前面的一个空格**，别的一个字节都没动。单位条在 dump 里根本不出现（busy overlay 下所有单位满血），所以另外单独量了一次：把 `c01-16` 的每个单位打到六个不同的血量、三个色档全部出现，42 个 rect 改动前后逐字节相同。`sweep` 不变——没有一条规则动过。

**一个 0..1 的比值，十二个算法。** `hp / maxHp` 和 `morale.current / morale.maximum` 在十二处各自算：七处直接除，一处防了上限为 0，两处夹到 0..1，一处两件都做。分歧已经到屏幕上了——`maxHp: 0` 的结构在通用美术下画满格血条（那边防了除法），在题材美术下画一条 `NaN` 宽的（那边没防）。现在只有 `gaugeRatio` 一处，守卫的 tell 是**左操作数**：从 `.hp` 或 `.current` 除出去才是量表读数，而 `damage / maxHp`、`healed / def.maxHp` 是另一个问题——「这一下相对目标有多大」，士气伤害正是按它缩放的，在那里夹到 1 会把重击悄悄削平。所以这条守卫不需要任何豁免名单。全部 20 张关卡 × 3 档 AI 的事件流与摘要、以及全部棋盘 markup，改动前后逐字节相同。

**加一条守卫，就先破坏一次。** 归属类守卫是靠正则扫源码的，一条永远为真的正则和一条正确的正则看起来一模一样。把被禁的写法手工写回去一次，确认它真的红了，再改回来——每一轮的新守卫都这么验过。当前共 99 条。

这一轮的破坏又抓到一次假通过：「算出来的答案必须有人读」第一次破坏（把 `CareerOption.mastered` 从界面上摘掉）是**绿的**——因为守卫自己的说明段落里写了 `CareerOption.mastered` 这几个字，而干草堆没有去注释，于是**解释这条禁令的那段话本身成了那个字段的读者**。去掉注释再破坏，红了。同一类错误在这份文件里已经出现第四次了：`stripStrings` 会留下模板串里的 `${…}`、`classList.toggle('x', …)` 会让一个类名为自己作证、把一个字面量搬进一个模块是被允许的搬法。守卫的干草堆是什么，和守卫的正则是什么，一样重要。

**性能守卫要计数，不要计时。** `__bench__` 一直只报数字，从不判定——回归了也是绿的。而一条墙钟阈值在负载高的机器上会假红、在快机器上会假绿。引擎在给定关卡与种子下是确定的，所以改成**数调用次数**：最重的一章（25 单位 / 25×17）跑 60 步 AI，`moveField`、`threatOf`、`pathTo` 的每步次数有上限。今天大约是每步 7 次移动域、10 次威胁图；上限放到 20 / 30 / 10，因为它要抓的是**数量级**，不是调优——一条跟每次重构吵架的门槛会被删掉。计数器用一个 `TacticalSpace` 装饰器注入，而且是作为**能力覆盖**装进组合的，顺带证明空间端口真的可替换。破坏验证：在候选循环里按目标重算一次移动域，当场红。

（装饰器用 `Object.create(inner)` 走原型委托，不是 `{ ...inner }`。`DefaultTacticalSpace` 是个类，展开只复制自有可枚举属性，没点名的那七个方法会直接消失——这个坑这轮踩了第二次。）

**同一个答案不要写两遍——而这件事需要守卫，不需要自觉。** `escapeAttr` 上面有一行注释写着它是从三份私有拷贝里收拢来的；等我这轮去看，旁边已经又长出了第四份。所以现在有一条守卫扫全部工作区包、四个应用入口和 `tools/`，把每个顶层声明（`const` / `function` / `type` / `interface`）**抹掉被声明的名字**之后规范化比对：同一份文本出现在两个文件里就是红的。抹掉名字是关键——`idHash`、`nameHash` 和一个嵌在画图函数里的 `hash` 是同一个函数的三个名字。这一轮它在改动前的树上找出十处：两份存档格式的字段检查词表（**而且已经分叉了**，一份叫 `orNull`、一份叫 `nullable`）、引擎里两份 `cloneAccounts`、FNV-1a 名字哈希四份、`pick` 四份、`r2` 四份、`definitionKey` 两份、`attr`/`escapeAttr` 两份、地形格上下文三份（还带两个名字）、以及四把尺子里三把各带一份棋盘挂载脚手架。

它豁免以 `Rules` 结尾的接口，理由是公理本身：「端口由需要它的消费者声明，`BattleRuleServices` 结构化满足它们」——`MovementRules` 和 `VisionRules` 都要铺法加目录，而且谁都不许 import 对方的模块，所以五组一模一样是设计而不是拷贝。长度下限 80 字符则是为了让 `{ readonly width: number; readonly height: number }` 过去：那是格数意义上的地图尺寸和场景单位意义上的画布，合并它们才是错。破坏验证：把名字哈希整份粘回一个模块并改名 `localHash`，当场报 `localHash == nameHash`。

**一条守卫的辅助函数也是承重的。** `stripStrings` 把字符串和模板字面量抹白，理由是「markup 和文案是数据，一条关于*代码*的守卫去读代码印出来的东西，守的是错的文本」。但它以前把模板字面量**整段**抹掉，`${…}` 也一起——而 UI 包几乎全是模板字面量，`${hpBar(unit.hp / definition.maxHp, 72)}` 里面是代码。于是十几条建在它上面的守卫对那些地方全是瞎的：HUD 里有一个 `objective.id!` 就那样待在一个 `${…}` 里，而禁止断言的那条守卫一直是绿的。

改成扫描器：字面量的文字丢掉，洞留下（洞里可以有对象字面量，可以有另一个模板字面量，可以再有一个洞，所以不是正则）。这类辅助函数失败起来是静默的——抹多了，每条守卫都因为什么都没读到而通过——所以它自己也有一条断言：洞里的表达式必须留下，任何深度的文案必须消失。破坏验证做了两次，都把违规写在 `${…}` 里面：一次断言，一次量表除法，两条守卫当场红。

**同一条公理不要两条守卫。** 这一轮我为「几何归铺法」新写了一条，写完才发现早就有一条「measures the board through its tiling」——而它漏了那个违规，原因有两个：只扫三个包（违规在战役包里），以及第一条 tell 要求整个两项曼哈顿表达式（半个式子、Chebyshev 都溜过去）。正确的动作是**合并**而不是并存：范围扩到全部工作区包与应用入口，tell 放宽到半个式子，然后把我新写的那条删掉。合并后按五种形状逐一破坏验证——两种是原来漏掉的，两种是原来就该抓到的，确认合并只放宽没削弱。两条守卫看同一条公理，迟早会一条说是一条说不是。

**破坏一次还不够，要把每一种写法都破坏一遍。** 上一轮的「不许用 `!` 断言」守卫只匹配 `x!.field` 和 `x![i]`——而我恰好也只用这个形状验了它。同一批文件里躺着十六个 `f()!`、`id!`、`g(x!)`，守卫一路绿灯。现在它针对断言运算符本身，四种形状逐一破坏验证过。

**守卫的作用范围本身就是一条断言。** 调用形状守卫原来只看「会 emit 的函数」，注释里写着「纯查询不管」——那条豁免恰好盖住了它本该消灭的东西：十五个查询仍是旧的 `(subject, content)` 形状，另有五个函数把两三个服务当成独立参数传。范围缩小得越顺理成章，越要问它盖住了什么。

**守卫的匹配式只覆盖了「产生值」的一种写法。** 「未绑定的 catch 不许产生值」原来只在 catch 体里搜 `return`——而赋值、副作用、抛一个新错误都是产生值。它漏掉了 AI 循环里的 `catch { events = tryDispatch(endTurn) }`（把规则层任何缺陷变成一次无声的过回合）和关卡存储里的 `catch { existing = [] }`（紧接着把空列表写了回去）。现在守卫按公理的字面执行：未绑定的 catch 体必须为空，并用注释说明为什么；其余一切都要绑定并查看那个错误。

**守卫按名字匹配，就只挡得住名字。** 「每个扩展点都建在共用注册表上」原来匹配 `export class \w*Registry`——而编辑器的工具集叫 `EditorToolbox`，一个手写 `Map` 加一个 `get`，其余一概没有；而且守卫只扫引擎。现在它按形状匹配：一个类自己持有键值表、又声明了 `register`/`define` 往里写，就必须建在基类上。两条豁免各有理由（版本阶梯、动画调度器），而不是「它不叫 Registry」。

**文档也可以被守卫。** 能力目录承诺「每条规则的归属都写在这里」，而五行点名的注册表早就加上了 `Default` 前缀——照着表去 grep `AiIntents`、`ResourceSubjectResolvers` 的读者什么都找不到。守卫只扫**表格行**：表格是对当下的断言，正文则必须能讲「这个名字被改成了什么、那个被删了」。范围一旦分对，这条守卫就既挡得住文档腐烂，又不妨碍文档讲历史。

**「没有第三种答案」也是一种漏判。** 本轮的错误分类守卫把引擎里八十四处裸 `throw new Error` 逼出来重新归类，多数确实是「调用方错了」。但其中一处两者都不是：增援落到有人站着的格子上——那是普通对局。它此前以裸 `Error` 抛出，穿过外壳唯一那道 `instanceof IllegalActionError` 判断，直接把战斗打断。分类的价值不在于换个类名，而在于逼你对每一处回答「这到底是谁的错」——答不上来的那一处，往往才是真正的缺陷。

**行首锚点会把「问句」放走。** 本轮的实体守卫第一版写成 `^\s*…\.field\s*=`，一次抓到八个模块。把锚点去掉、再把 `+=` 也算进去之后，又掉出两处：`if (commander) commander.owner = …` 和 `if (leader.commanderId === null) leader.commanderId = …`——两条都是**写在 `if` 后面同一行**的赋值。守卫每多要求一个字符，就多放走一类写法；而放走的这一类恰好是「顺手补一句」的那一类，也就是最可能绕过归属的那一类。

**抄一个字段，就抄了一个问题。** 本轮的端口守卫（每个 `XxxRules` 只许声明本模块自己读的字段）报出十七处（十六处改掉，一处按理由豁免），它们不是十七处样板：五个端口各写了一遍 `GridRules` 的 `grids`，`AiRules` 抄了 `turnOrders` 而 `AiTurnContext` 紧接着把 `activeTurnOrder` 的函数体重写了一遍，`WeaponAreaRules` 声明了自己一次也没读过的 `areaShapes` 而「一次打击覆盖哪些格」在两个模块里各写了一份。字段被抄走，是那条规则没有归属的最早征兆——比重复的表达式更早。

**守卫查的是比较，硬写成数据的 id 它看不见。** 本轮加的「不许拿 ability id 猜这条命令是什么」按 `x.ability === '…'` 两个方向匹配，六处违规当场落网。第七处不是比较：点敌人自动选位后，`commandClick` 把选出来的那条命令按 `'attack'` 这个字面量装进 `TargetSelection`，正则一个字都对不上。抓到它的是行为测试——一套只有内容包自己的「齐射」、没有 `attack` 的规则集，点下去必须把齐射举起来。归属类守卫只能证明「没人在问 id」，证明不了「没人在替 id 做主」；这一半要靠一个不含核心 id 的规则集去跑。

**还要读失败信息本身。** 破坏验证时我两次用 `grep -c FAIL` 判断，而 vitest 把那行写到 stderr，脚本一直读到 0 —— 于是「没抓到」被我读成「抓到了」。现在逐条确认失败信息里真的点出了被破坏的那个符号。

**守卫的扫描范围也是它的一部分。** 题材包此前不在任何守卫的视野里，于是那里藏着一个 `catch { return null }`——「这个包没有这张图标」和「素材解析坏了」被答成同一个 null。把题材包加进扫描范围之后它当场就被点了出来。

新守卫也会抓到自己那一轮的东西：本轮加空间层守卫时，无环守卫立刻报出 `spatial.ts -> state.ts -> domain/map-layers.ts -> spatial.ts`——一个纯几何函数住在耦合了状态的模块里，这才是那条环的根因。

## 性能基准

运行核心 benchmark：

```bash
npm run bench:core
```

遵守测量驱动原则：

1. 先记录可复现的关卡、单位数和运行环境
2. 找到占总耗时主要比例的路径
3. 修改一个瓶颈
4. 同时运行正确性测试和 benchmark
5. 记录中位数、波动和内存影响

不要用一次本地运行的绝对时间设硬门槛。基准更适合比较同一机器上的前后变化。

缓存必须有失效测试。任何为了性能引入的缓存都不能成为第二状态真值。

## 构建验收

`npm run build` 依次构建：

1. 主游戏
2. 编辑器
3. 引擎能力 Demo
4. 超级体验关卡

构建后检查：

- 每个 `dist/*/index.html` 存在
- 主游戏和编辑器通过 HTTP 预览可打开
- 单文件体验包通过 `file://` 可打开
- 图片、CSS 和字体没有外部相对路径遗漏
- 浏览器控制台没有模块、跨域或素材 404 错误
- 页面销毁后没有残留浏览器自动化进程
