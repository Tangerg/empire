# 使用 SRPG 关卡编辑器

本页说明当前可视化编辑器能完成的关卡制作工作、操作方式和数据边界。编辑器面向基础战术地图，不是完整的场景脚本或战役编辑器。

> 文档类型：How-to · 状态：基础地图制作闭环已实现 · 代码真值：`packages/editor/src/`、`apps/editor/`



## 没有字的控件也要有名字

编辑器工具栏上的撤销/重做、删除玩家，以及主菜单里删除自制关卡——这四个按钮的全部内容就是一个图标：屏幕阅读器读不到东西，鼠标悬停也没有提示。而这套代码本来就知道该怎么做：战斗 HUD 里每一个纯图标按钮都带 `title`。

顺带修掉一处更直接的：**重做按钮画的是 `play`**——一个三角形，读起来是「开始」——因为图标集里没有别的候选。现在加了 `redo`，就是 `undo` 那道弧线镜像过去。

守卫扫的是形状：一个 `<button>`，把 `${icon(...)}` 挖掉之后内容为空，就必须带 `title` 或 `aria-label`；而 `${escapeHtml(player.name)}` 这样的洞算作有字。

## 新建的文档一开就是干净的

`emptyLevel` 的注释写着「一张空白的、**合法的**关卡」，而它交出来的关卡带着两条错误：两边都既没有单位也没有生产建筑，也就是引擎自己的 lint 说的「开局即败」。于是编辑器一打开，右边就是一张红色的错误卡，对着一份还没人碰过的文档；而它默认的胜利条件是「歼灭所有敌军」——一个敌人都没有。

现在空白文档给两边各放一处能造兵的地形，摆在中间那行的两端。**哪种地形能造兵是问目录的**（`terrains.all()` 里第一个 `produces` 非空的），和空白地面本来就是问 `terrainEncoding.defaultCharacter` 一样——这里不写死任何内容 id。要是某套规则集根本没有能造兵的地形，那就还是一片空地，lint 照旧报出来：对那样的规则集，这是诚实的答案。

守它的测试在 `level-lint.test.ts`：空白文档的错误列表必须是空的，两边各拥有一格且不是同一格。把那处地形查询换成 `null`，它会把那两条「开局即败」原样报回来。

**还差一半**：第一版给了两边兵营却没给钱——lint 干净，实际上谁也造不出兵，而「试玩」按钮就把这么一份东西交给了游戏：两支空军队隔着河对望。开局的钱现在也是问目录要的：这座兵营能造的东西里最便宜的那一个。于是在一张新地图上能做的第一件事，就是往上面放一个兵。

## 试玩按钮跳的是游戏,不是编辑器自己

`试玩` 把关卡存进 sessionStorage 然后跳转，游戏在加载时把它取出来。跳转的地址原来是 `./index.html`——**从编辑器自己的目录出发，那就是编辑器**。于是按下试玩，页面重新加载编辑器，而那份关卡躺在 sessionStorage 里等一个永远不会打开的读者。

同样的错还有一处：引擎 Demo 左上角的「返回游戏」是 `href="./"`，也是它自己。而游戏跳编辑器用的一直是 `../editor/index.html`——三者现在口径一致。

这条路是唯一跨两个应用的路径，`ui:play` 现在会走它：打开编辑器、按试玩、等游戏把棋盘挂出来，再问一遍有没有格子被界面压住。

守卫立起来之后**第一次跑就又抓到一处**：编辑器工具栏左上角那个「返回游戏」按钮，同样链到 `./index.html`。规则很简单——**跳到自己那一页不是导航，是把 reload 写长了**；真要重载就写 `location.reload()`。顺带也检查 `../某个应用/` 里的那个应用是不是真的存在。

## 启动编辑器

从仓库根目录启动：

```bash
npm install
npm run dev --workspace @empire/editor-app
```

Vite 会输出本地地址。通过该地址打开编辑器，不要直接双击 `apps/editor/index.html`，浏览器会阻止模块通过 `file://` 加载。

主游戏菜单也可以打开构建后的编辑器页面。`npm run build` 会把编辑器输出到 `dist/editor/`。

## 制作基础地图

编辑器把可修改状态保存在 `EditorDocument`，渲染和 DOM 交互保存在 `EditorApp` 与 `EditorBoard`。所有笔刷操作先修改文档聚合，再重新渲染。

工具集由宿主通过 `EditorSetup.tools` 显式提供。`EditorApp` 在打开时 clone 并封存这份注册表；扩展工具必须在组合根注册，不能靠修改模块级默认值影响已经运行的编辑器。

### 绘制地形

顶部工具栏提供：

| 工具 | 快捷键 | 行为 |
| --- | --- | --- |
| 笔刷 | `B` | 使用 1×1 或 3×3 笔刷绘制地形 |
| 矩形 | `R` | 从起点拖到终点填充矩形 |
| 填充 | `F` | 四方向洪水填充同类地形 |
| 海拔 | `H` | 绘制整数高度，右键归零 |
| 悬崖边 | `J` | 从一个格拖到正交相邻格切换悬崖 |
| 方向掩体 | `K` | 在选定方向绘制半掩体或全掩体 |
| 放置单位 | `U` | 用当前兵种与归属放置单位 |
| 归属 | `O` | 设置可占领地形的玩家归属 |
| 擦除单位 | `E` | 删除当前格单位 |
| 吸取 | `I` | 读取格上的地形、单位或归属 |

右键在笔刷、海拔、掩体和归属工具中执行对应擦除。按数字 `1` 至 `9` 可以选择内容目录中的前九种地形。

### 配置空间层

海拔、悬崖和方向掩体是三个独立图层：

1. 选择海拔工具并输入高度
2. 在需要的格上绘制高地
3. 使用悬崖工具连接禁止跨越的相邻格
4. 选择北、东、南或西方向
5. 选择半掩体或全掩体并绘制格边

编辑器会显示海拔徽标、悬崖线和掩体边。单位放在不可通行地形上时，棋盘会显示错误染色，右侧检查器也会报告问题。

### 放置单位和据点归属

先选择归属，再选择单位。放置新单位会替换该格已有单位，避免编辑器主动制造重叠。

归属工具只修改可占领地形。把据点重绘为普通地形会清除其归属，避免序列化无效 owner。

编辑器中的单位表来自启动时安装的内容包。更换题材内容时，应在 `apps/editor/src/main.ts` 的组合根安装对应 `ContentPack`。

## 配置玩家和基础规则

右侧面板可以编辑：

- 玩家名称、颜色和 team
- `human` 或 `ai` 控制器
- 初始资金
- AI aggression
- 四种基础玩家目标
- 战争迷雾和反击
- 新兵能否立即行动
- 即时或渐进占领
- 回合上限
- 基础资金产出和据点资金覆盖
- 每玩家单位上限
- 当前引擎已安装的行动顺序策略（选项直接来自 `rules.turnOrders`，题材插件新增策略无需修改编辑器）

编辑器支持添加玩家，并在玩家数大于 2 时删除玩家。删除玩家前应先清除其单位与据点归属，否则校验会报告悬空引用。

### 基础目标

可视化表单当前支持：

- 歼灭敌军
- 攻占城堡
- 控制全部据点
- 坚守回合

玩家未选择独立目标时，使用“通用胜利条件”。复杂目标和 `surviveTurns.turns` 等参数仍需要在 TypeScript 或 JSON 中配置。

## 调整地图尺寸

编辑器允许宽高为 4 到 64 格。缩放以左上角为锚点：

- 放大区域填充平原、0 海拔和中立归属
- 缩小会裁掉超出边界的地形、单位、悬崖和方向掩体
- 裁剪不可逆，但可以立即撤销

修改尺寸只会重建基础地图层；`EditorDocument` 会继续原样携带它不提供表单的高级关卡段落，但不会替你校正这些段落里的坐标。复杂关卡缩放后必须重新校验区域、部署区、结构和场景触发器所引用的位置。

## 使用历史、草稿和缩放

编辑器保存最多 80 个文档快照。使用以下操作：

- `Ctrl+Z` 或 `⌘Z`：撤销
- `Ctrl+Shift+Z` 或 `⌘Shift+Z`：重做
- `Ctrl+S` 或 `⌘S`：保存到“我的关卡”
- `Ctrl+滚轮` 或 `⌘+滚轮`：缩放棋盘
- 顶部加减按钮：缩放棋盘
- `Esc`：取消未完成的矩形

每次有效修改会写入 `localStorage` 的 `empire.editorDraft`。刷新页面后，应用入口可以恢复草稿。

## 保存、导入和导出

编辑器提供三种持久化方式：

- **保存**：写入浏览器“我的关卡”列表，即使存在校验错误也允许保存草稿
- **导出**：下载格式化的 schema 2 JSON
- **复制 JSON**：写入剪贴板

导入流程会先执行：

1. JSON 解析
2. `normaliseLevel()`
3. `mapFromLevel()` 地形网格检查
4. 替换当前 `EditorDocument`

导入成功不代表关卡可以运行。右侧检查器会继续执行 `validateLevel(rules, level)` 并列出错误和警告——它一次问完文档自洽与规则集实现两件事。

## 校验和试玩

编辑器在每次渲染右侧面板时校验当前关卡。错误会阻止试玩，警告不会阻止。

试玩按钮执行：

1. 导出当前 `LevelData`
2. 运行 `validateLevel()`
3. 把关卡临时写入浏览器存储
4. 跳转到游戏入口消费该临时关卡

当前独立 `apps/editor` 的相对跳转仍指向自身 `index.html`，因此完整试玩流程应从主游戏集成入口或与游戏输出相邻的部署结构触发。该问题属于应用路由边界，不影响文档聚合和 JSON 制作。

## 编辑器不结构化编辑的字段

`EditorDocument` 有可视化工具的部分是：

- ID、名称、作者和说明
- 基础地形、归属、海拔、悬崖和方向掩体
- 单位
- 玩家及其资源和基础 AI 数据
- 局部规则
- 通用目标

其余部分——指挥官、结构与复合目标、场景区域／覆盖层／触发器／交战政策、战前部署、`extra`——**原样保留**（`PreservedLevelSections`），只是没有表单。打开一张脚本化战役关卡、改一格地形再保存，不会丢掉它的触发器或部署区。`document.test.ts` 里有一条往返测试盯着这份清单，`LevelData` 每长一个字段都要过它。

因此“导入、修改、导出”对生产关卡是安全的。仍然建议把高级字段维护在内容包源码里，理由不是会丢，而是可读性与可评审性：

1. 在编辑器创建基础地图
2. 导出 schema 2 JSON 或复制 TypeScript 数据
3. 在内容包中加入结构、区域、目标、触发器和部署
4. 使用 `validateLevel()` 与测试验证最终关卡

## 编辑器不知道自己在编哪个游戏

编辑器包里没有任何内容 id，也不 import 任何 `@empire/content-*` / `@empire/story-*`：

- 空白地面来自 catalog 的 `terrainEncoding.defaultTerrain`（右键擦除、地图扩容、`emptyLevel` 都用它）
- 笔刷初始兵种是调色板的第一项
- 可打开的内置关卡由应用组合根通过 `EditorSetup.presets` 注入

```ts
new EditorApp({ rules, presets: [...ANCIENT_EMPIRES_LEVELS, ...CANDIDATE_01_LEVELS] }, level);
```

`editor.test.ts` 里有两条守卫：一条禁止编辑器源码出现已发布目录里的任何 id 或 import 任何题材包，一条用一个只有 `sand`／`nomad` 的目录验证擦除行为。

## 扩展编辑器

新增可视化能力时保持三层职责：

| 层 | 职责 |
| --- | --- |
| `EditorDocument` | 数据修改、不变量、序列化和往返 |
| `EditorBoard` | SVG 图层、命中测试和可视错误标记 |
| `EditorTool` / `EditorToolRegistry` | 单个工具的身份、快捷键、高亮和笔画行为；工具集是开放注册表 |
| `BrushSettings` | 调色板状态：地形、兵种、归属、笔刷尺寸、海拔、掩体方向与等级 |
| `EditorApp` | DOM、历史、存储和命令委派 |

工具是策略而不是 `switch` 分支，与引擎的 Action 处理器同构。每个工具只声明两件事之一：

- `paint()`：连续工具，拖动过程中每一次采样都作用一次
- `commit()`：两段式工具（矩形、悬崖边），按下记录锚点、松开时一次成交

`EditorToolRegistry` 拒绝重复 id 和被遮蔽的快捷键——工具表和快捷键表曾经是两份声明，结果海拔、悬崖和掩体三个工具的提示里写着快捷键却没人监听。

它和引擎里每个扩展点一样建在共用注册表基类上：`register` / `replace` / `keys` / `clone` 都在。此前它是一个手写 `Map` 加一个 `get`，于是「工具集是要长大的」这句注释对契约是真的、对代码是假的——插件既加不了工具，也换不了工具。共享的 `EDITOR_TOOLS` 已封存；宿主先 clone、增改，再通过 `EditorSetup.tools` 交给编辑器，编辑器会再次 clone 并封存自己的运行时副本。

扩展步骤：

1. 先让 `EditorDocument` 往返目标字段
2. 为领域修改添加文档测试
3. 再加入一个 `EditorTool` 或表单字段
4. 在棋盘层加入必要可视化
5. 更新导入、撤销、缩放和清空行为
6. 添加 DOM 交互测试和应用启动测试
7. 更新[引擎能力目录](./engine-capabilities.md)

不要直接从 DOM 修改 `LevelData`，也不要在 `EditorBoard` 中复制战斗合法性。编辑器的最终关卡合法性始终由 `validateLevel(rules, level)` 判定，和引擎建状态时问的是同一个函数。
